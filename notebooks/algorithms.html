Что такое алгоритм и зачем считать операции

Определение. Алгоритм — конечное однозначное предписание: последовательность команд, которые исполнитель выполняет шаг за шагом.

Своими словами. Рецепт для компьютера. «Однозначное» значит: на каждом шаге ясно, что делать дальше (нет «ну, примерно так»).

Пример. «Сложить все элементы массива a[0…n−1]»: положить s = 0; для i от 0 до n−1 делать s = s + a[i]; вернуть s. Это алгоритм.
Не-пример. «Найди красивое решение» — не алгоритм: нет конечного списка проверяемых шагов.

Почему не секунды на ноутбуке? Один и тот же код на разном железе даёт разное время; сравнивать алгоритмы так нельзя. Сравнивают число элементарных операций как функцию размера входа n (длина массива, число цифр, …).

Линейка железа (с пары). Процессор ≈ 2.3 GHz → грубо ~ 2·10⁹ тактов/сек. Не каждый такт = полезная операция: осторожная оценка ~10⁸–4·10⁸ полезных операций в секунду. В олимпиадной культуре часто держат ~10⁸ оп/сек.
Как пользоваться линейкой. Алгоритм делает ~ n² сравнений, n = 10⁴ → ~10⁸ операций → около секунды на грани. Если n = 10⁶ и алгоритм n² → ~10¹² — за секунду не уложится. Линейный проход n = 10⁶ — нормально.

Своими словами. Это не теорема, а линейка «влезет ли в лимит времени». Дальше важнее порядок роста, а не точная константа.

Пример: вложенные циклы и ≈ n²

На доске схема вроде:

for i = 0 … n:
    for j = 0 … i:
        ans += …   # константа «мелких» операций, на паре множитель 5

Шаг 1. Зафиксируй i. Внутренний цикл делает примерно i+1 шагов (j от 0 до i).

Шаг 2. Сложи по всем i:

0 + 1 + 2 + … + n = n(n+1)/2.

Шаг 3. Если внутри ещё константа k мелких операций (на доске k = 5):

T(n) = 5 · n(n+1)/2 = (5/2) n² + (5/2) n.

При больших n доминирует (5/2)n² → говорят «порядка n²» или Θ(n²).

«Треугольник» итераций: сумма высот 0…n даёт квадрат по порядку.
Числа. n = 10 → сумма = 55, с множителем 5 → T ≈ 275. n = 100 → сумма = 5050, T ≈ 25250. Рост в ≈ 100 раз при n×10 — как у квадрата.

Своими словами. Два вложенных цикла «до i» → квадрат. Константа 5 при больших n почти не важна — важен порядок.

Асимптотика: O, Θ, Ω, o, ω

Нужен язык: «f растёт не быстрее g», «тот же порядок», «строго медленнее». Это и есть большая O и компания.

ЗнакИнтуицияКартинка
f = O(g)f ≲ g — верхняя оценкаf не выше C·g с какого-то N
f = Ω(g)f ≳ g — нижняя оценкаf не ниже C·g
f = Θ(g)f ≍ g — один порядокзажат между C₁g и C₂g
f = o(g)f ≪ g — строго медленнееf/g → 0
f = ω(g)f ≫ gf/g → ∞
Порядок роста
f = O(g) — верхняя оценка  f = Θ(g) — тот же порядок
Θ (как на паре). f = Θ(g), если ∃ N > 0, C₁ > 0, C₂ > 0 такие, что для всех n ≥ N:
C₁ · g(n) ≤ f(n) ≤ C₂ · g(n).
O. f = O(g), если ∃ N, C > 0: ∀ n ≥ N выполняется 0 ≤ f(n) ≤ C · g(n).
Ω. f = Ω(g), если ∃ N, C > 0: ∀ n ≥ N выполняется f(n) ≥ C · g(n).

Своими словами. «С какого-то момента для всех n…» — тот же дух, что ε‑δ в матанализе, только вместо ε — константы C. Запись f = O(g) лучше читать «f принадлежит классу O(g)»; поэтому «O(g) = f» бессмысленно.

Θ: кривая f зажата между двумя кратными g.

Шкала роста (запомни порядок):

log n ≪ (log n)² ≪ √n ≪ n ≪ n log n ≪ n¹·¹ ≪ n² ≪ 2ⁿ ≪ n!

Пример. 3n² + 10n + 1 = Θ(n²): доминирует n².
Не-пример. n³ ≠ O(n²): отношение n³/n² = n → ∞, никакая константа C не удержит для всех больших n.
Школьное умножение n-значных — O(n²); Карацуба показывает, что квадрат — не предел.

Как на практике «доказывать» O и Θ

Показать f = O(g)

Нужно найти C и N такие, что f(n) ≤ C·g(n) при n ≥ N. Часто берут «все младшие члены ≤ главному».

Показать: 3n² + 10n + 1 = O(n²).
При n ≥ 1: 10n ≤ 10n², 1 ≤ n² → 3n²+10n+1 ≤ 3n²+10n²+n² = 14n². Берём C = 14, N = 1. ✓

Показать f = Θ(g)

Нужны и верх, и низ. Верх — как для O. Низ: отбросить положительные младшие или оценить снизу главным членом.

Тот же f = 3n²+10n+1. Снизу: f(n) ≥ 3n² при всех n ≥ 0. Значит C₁ = 3, C₂ = 14 → Θ(n²). ✓

Показать, что НЕ O

Доказать: ∀ C, N найдётся n ≥ N с f(n) > C·g(n). Обычно смотрят предел f/g = ∞.

n³ / n² = n → ∞ ⇒ n³ ≠ O(n²).

Частые ловушки

  • O — верхняя оценка: n = O(n²) — правда (медленное «влезает» в быстрое сверху).
  • Θ симметрична: f=Θ(g) ⟺ g=Θ(f). O — нет: из f=O(g) не следует g=O(f).
  • O(1) значит «ограничено константой», не обязательно ровно одна операция.
  • Смена основания логарифма: log₂ n = Θ(log₁₀ n) (множитель 1/ln 10 — константа).

Число как многочлен; умножение через многочлены

Многочлен степени n: A(x) = a₀ + a₁ x + a₂ x² + … + aₙ xⁿ.

Любое число в позиционной системе — тот же многочлен, где x = основание системы.

Пример. 12345 в десятичной:
12345 = 5·10⁰ + 4·10¹ + 3·10² + 2·10³ + 1·10⁴.
Замени 10 на переменную x → многочлен A(x) = 5 + 4x + 3x² + 2x³ + x⁴. На паре: «x — просто переменная»; «10 сс» = десятичная система.

Зачем это для умножения. Чтобы умножить числа A и B:

  1. взять их многочлены A(x), B(x);
  2. перемножить многочлены (как в алгебре);
  3. подставить x = основание (10) и разобраться с переносами, если коэффициент ≥ 10.
Коротко: A × B ↔ A(x)·B(x) при x = основание.
Крошечный пример. 23 · 45. Многочлены: 2x+3 и 4x+5.
(2x+3)(4x+5) = 8x² + 10x + 12x + 15 = 8x² + 22x + 15.
x=10: 8·100 + 22·10 + 15 = 1035. ✓ (переносов не понадобилось — коэффициенты < 10, кроме того что 22 уже «как бы с переносом», но при подстановке всё честно).

Своими словами. Большое число — «многочлен, посчитанный в точке 10». Умножать числа ≈ умножать такие многочлены. Дальше — как умножать многочлены быстрее, разрезая пополам (Карацуба).

Карацуба: зачем вообще что‑то выдумывать

Школьное умножение «в столбик» двух n‑значных чисел: каждую цифру первого умножаешь на каждую цифру второго → порядка n × n = n² одноразрядных умножений. При больших n это дорого.

Своими словами. Цель Карацубы — умножать длинные числа быстрее, чем n², разрезая их пополам и аккуратно экономя тяжёлые умножения половин.

Дальше удобно думать так: число = «две половины». Для десятичной системы с чётным числом цифр:

Пусть у числа n цифр, m = n/2. Тогда
X = A · 10ᵐ + B,   Y = C · 10ᵐ + D,
где A, B, C, D — числа примерно с m цифрами (старшая и младшая половины).
Пример разреза. X = 23, Y = 45, берём m = 1 (половина «по одной цифре»):
23 = 2·10 + 3 → A = 2, B = 3;
45 = 4·10 + 5 → C = 4, D = 5.
Каждое число режем на старшую и младшую половины.

Наивный «разделяй и властвуй»: 4 умножения

Раскроем скобки (школьная алгебра):

X·Y = (A·10ᵐ + B)(C·10ᵐ + D)
= AC · 10²ᵐ + (AD + BC) · 10ᵐ + BD.

Три «блока» результата:

  1. AC — сдвигаем на 2m разрядов влево (× 10²ᵐ);
  2. AD + BC — сдвигаем на m разрядов (× 10ᵐ);
  3. BD — без сдвига.

Чтобы получить все три блока, кажется, нужны четыре умножения половин: AC, AD, BC, BD. Сложения и сдвиги дешёвые (линейные по длине числа), а вот умножение половин — дорогое, его и считаем в рекуррентности.

Те же 23 × 45.
AC = 2·4 = 8;
AD = 2·5 = 10;   BC = 3·4 = 12;   AD+BC = 22;
BD = 3·5 = 15;
Итог: 8·100 + 22·10 + 15 = 800 + 220 + 15 = 1035. Проверка: 23·45 = 1035. ✓

Сложность. T(n) = 4 T(n/2) + O(n). По мастер-теореме a=4, b=2, c=1 → q = 4/2 = 2 → T = Θ(n^{log₂ 4}) = Θ(n²). Разрезали пополам, а порядок тот же квадрат — выигрыша нет.

Своими словами. Резать пополам полезно только если число тяжёлых умножений станет меньше четырёх.

Трюк Карацубы: как обойтись тремя умножениями

Смотрим на тождество (просто раскрой правую часть):

(A + B)(C + D) = AC + AD + BC + BD = AC + BD + (AD + BC).

Отсюда середина, которая нам нужна:

AD + BC = (A + B)(C + D) − AC − BD.

Своими словами. Вместо двух умножений AD и BC делаем одно умножение сумм (A+B)·(C+D), а потом вычитаем уже известные AC и BD. Вычитание — дёшево; умножение — дорого.

Алгоритм Карацубы на одном уровне:

  1. P₀ = A · C   (одно умножение половин)
  2. P₂ = B · D   (второе)
  3. P₁ = (A + B)(C + D) − P₀ − P₂   (третье умножение + два вычитания)
    после этого P₁ = AD + BC
  4. Собрать ответ: X·Y = P₀ · 10²ᵐ + P₁ · 10ᵐ + P₂
Три тяжёлых умножения → собираем три блока результата.

Тот же пример целиком: 23 × 45

A=2, B=3, C=4, D=5, m=1.

  1. P₀ = A·C = 2·4 = 8
  2. P₂ = B·D = 3·5 = 15
  3. (A+B)=5, (C+D)=9 → 5·9 = 45
    P₁ = 45 − 8 − 15 = 22  (это как раз AD+BC = 10+12)
  4. ответ = 8·10² + 22·10¹ + 15 = 800 + 220 + 15 = 1035
Ещё один пример, подлиннее: 1234 × 5678.
Режем по 2 цифры (m=2, основание 100): A=12, B=34, C=56, D=78.
P₀ = 12·56 = 672;
P₂ = 34·78 = 2652;
(A+B)=46, (C+D)=134 → 46·134 = 6164;
P₁ = 6164 − 672 − 2652 = 2840;
ответ = 672·10000 + 2840·100 + 2652 = 6 720 000 + 284 000 + 2652 = 7 006 652.
Проверка: 1234·5678 = 7 006 652. ✓

Своими словами. На бумаге для 2‑значных чисел Карацуба выглядит избыточно. Смысл — когда A, B, C, D сами длинные: каждое «·» снова режется рекурсивно теми же тремя умножениями.

Почему это быстрее n²

На каждом уровне: 3 рекурсивных умножения половин + O(n) на сложения/вычитания/сдвиги.

T(n) = 3 T(n/2) + O(n).

Мастер-теорема: a=3, b=2, c=1 → q = 3/2 = 1.5 > 1 → T = Θ(n^{log₂ 3}).

log₂ 3 ≈ 1.585, поэтому ≈ Θ(n¹·⁵⁸⁵). Это уже строго медленнее квадрата: при больших n Карацуба обгоняет «столбик».

МетодТяжёлых умножений половинПорядок
столбик / 4 произведения4Θ(n²)
Карацуба3Θ(n^{log₂ 3}) ≈ Θ(n¹·⁵⁸⁵)
Когда не гонять Карацубу. На маленьких n константы, сложения и накладные расходы рекурсии съедают выигрыш (задача 16 с практики). В коде обычно: «если длина < порога — умножай в лоб». Асимптотика — про большие входы.

Слово «Фурье» на паре — намёк на ещё более быстрое умножение через FFT; это следующий уровень после Карацубы, пока достаточно знать: квадрат — не предел.

Рекуррентности и дерево рекурсии

Рекуррентность для времени — формула «время на размере n через время на меньших размерах».
Каркас с пары: T(n) = a · T(n/b) + f(n).
a подзадач размера n/b, плюс работа f(n) «снаружи» (слияние, сложения, …).

Своими словами. Разделил задачу → решил куски → склеил. Время = время кусков + склейка.

Как читать дерево

  • Корень: размер n, работа на этом уровне ≈ f(n).
  • Уровень 1: a узлов размера n/b.
  • Уровень i: aⁱ узлов размера n/bⁱ.
  • Глубина до «листьев» размера ≈ 1: около log_b n уровней.

Если f(n) = nᶜ, работа уровня i:

aⁱ · (n/bⁱ)ᶜ = nᶜ · (a / bᶜ)ⁱ = nᶜ · qⁱ,   где q = a/bᶜ.

Полное время ≈ nᶜ · (1 + q + q² + … + qᴸ), L ≈ log_b n — сумма геометрической прогрессии.

Дерево: a ветвей из каждого узла, глубина ~ log_b n.
Пример с пары. T(n) = 3 T(⌊n/2⌋) + O(n) — три подзадачи половины, склейка линейная. Это как раз Карацуба: потом получим O(n^{log₂ 3}) ≈ O(n¹·⁵⁸).
Другая картинка: корень n → три ребёнка n/3 → … для T(n) = 3 T(n/3) + …

⚡ Быстрый тест: в чат Cursor напиши тест рекуррентности-и-дерево-реку — несколько коротких вопросов по всему блоку, потом сверка.

Мастер-теорема: постановка и q

T(n) = a T(n/b) + nᶜ,   где a ≥ 1, b ≥ 2, c ≥ 0.
Глубина дерева L ≈ log_b n.
q = a / bᶜ — отношение «сколько подзадач» / «насколько дешевеет работа nᶜ при уменьшении размера».

Работа уровней: nᶜ, nᶜ q, nᶜ q², … Сумма геометрической прогрессии:

1 + q + q² + … + qᴸ = (qᴸ⁺¹ − 1)/(q − 1)   (если q ≠ 1);   при q = 1 сумма = L+1 ≈ log_b n.

Своими словами. Смотришь на q: работа по уровням растёт, падает или стоит. От этого зависит, кто побеждает — корень, листья или все уровни вместе.

Три случая мастер-теоремы

УсловиеОтветИнтуиция
q < 1T = Θ(nᶜ)работа убывает вниз → доминирует «верх» (корень)
q = 1T = Θ(nᶜ log n)на каждом уровне ≈ nᶜ, уровней log → умножить на log
q > 1T = Θ(n^{log_b a})работа растёт вниз → доминируют листья; a^{log_b n} = n^{log_b a}

Почему при q > 1 появляется log_b a

Число листьев ≈ aᴸ, L = log_b n → a^{log_b n}. Известное тождество: a^{log_b n} = n^{log_b a}. Каждый лист — константа работы → порядок n^{log_b a}.

Разобранные примеры

4 умножения половин. a=4, b=2, c=1 → q = 4/2 = 2 > 1 → Θ(n^{log₂ 4}) = Θ(n²).
Карацуба. a=3, b=2, c=1 → q = 1.5 > 1 → Θ(n^{log₂ 3}) ≈ Θ(n¹·⁵⁸⁵).
Mergesort. T(n)=2T(n/2)+n → a=2,b=2,c=1 → q=1 → Θ(n log n).
q < 1. T(n)=2T(n/2)+n² → q = 2/4 = ½ < 1 → Θ(n²): склейка наверху дороже всей «нижней» работы.
Бинарный поиск / T(n)=T(n/2)+1. a=1,b=2,c=0 (n⁰=1) → q = 1/1 = 1 → Θ(log n).

На доске иногда писали O вместо Θ — для «порядка» на практике часто имеют в виду тот же класс. Аккуратнее в ответах практики ставить Θ, когда зажаты сверху и снизу.

Как читать циклы (с выводом, не только таблица)

1. Один цикл до n

for i = 1 … n:  // тело O(1)
→ n итераций → Θ(n)

2. Шаг 2

for i = 1; i ≤ n; i += 2
→ примерно n/2 итераций → всё ещё Θ(n) (константа 1/2 не меняет порядок)

3. Удвоение

for i = 1; i ≤ n; i *= 2
→ i = 1,2,4,…,2^k ≤ n → k ≈ log₂ n → Θ(log n)

Своими словами. Каждый раз удваиваешь — быстро добегаешь до n; шагов мало, логарифм.

4. Два вложенных до n

for i = 1…n:
  for j = 1…n: …
→ n·n = Θ(n²)

5. Треугольник j=1…i или j=i…n

for i = 1…n:
  for j = 1…i: …
→ Σᵢ i = n(n+1)/2 = Θ(n²)

То же для j=i…n: снова треугольник, Θ(n²).

6. Снаружи n, внутри удвоение / деление

for i = 1…n:
  for j = n; j ≥ 1; j /= 2: …
→ внешний n, внутренний ~ log n → Θ(n log n)
for i = 1; i ≤ n; i *= 2:
  for j = 1…n: …
→ внешний log n, внутренний n → Θ(n log n)

7. Внутри от i зависит логарифм

for i = 1…n:
  j = i
  while j ≥ 1: j /= 2
→ для каждого i около log i шагов → Σ log i = Θ(n log n)
Пары (i,j) с 1≤i≤j≤n. Число пар = n(n+1)/2 = Θ(n²) — снова треугольник, даже без явного «for j».

Практика 1 — полный разбор с пояснениями

Задача 1. Упорядочить по росту

Нужный порядок:

log n < (log n)² < √n < n < n log n < n¹·¹ < n² < 2ⁿ < n!

Почему так: логарифм растёт медленнее любого положительного степенного; √n = n^{1/2} < n; n log n = o(n¹·¹) потому что log n / n^{0.1} → 0; экспонента обгоняет любой полином; факториал обгоняет экспоненту (Стирлинг). Из списка почти никого не склеить в одну Θ-группу. Θ-эквивалентны были бы log₂ n и log₁₀ n — их здесь нет рядом.

Задача 2. Правда / ложь — почему

  1. n² = O(n³) — да: n² ≤ 1·n³ при n ≥ 1.
  2. n³ = O(n²) — нет: отношение → ∞.
  3. 3n²+10n+1 = Θ(n²) — да (см. разбор выше).
  4. log₂ n = Θ(log₁₀ n) — да: log₂ n = log₁₀ n / log₁₀ 2.
  5. 2ⁿ = O(3ⁿ) — да: (2/3)ⁿ → 0, значит 2ⁿ ≤ 1·3ⁿ.
  6. 3ⁿ = O(2ⁿ) — нет.
  7. n log n = O(n²) — да.
  8. n² = O(n log n) — нет.

Задача 3. Упростить до Θ

  1. 7n³+2n²+100 → доминирует n³ → Θ(n³)
  2. n² + n log n + 1000n → доминирует n² → Θ(n²)
  3. (n+1)² − n² = 2n+1 → Θ(n) (разность « соседних квадратов»)
  4. Σᵢ₌₁ⁿ i = n(n+1)/2 → Θ(n²)
  5. Σᵢ₌₁ⁿ log i: сумма ≈ ∫ log x dx = n log n − n → Θ(n log n)

Задачи 4–7. Циклы

4. for 1..n → Θ(n); шаг 2 → Θ(n); i*=2 → Θ(log n). (См. раздел «Циклы».)

5. n×n → Θ(n²); j=1..i → Θ(n²); внешний n + внутренний *=2 → Θ(n log n); внешний *=2 + внутренний n → Θ(n log n).

6. для каждого i цикл j/=2 даёт ~ log i → Σ log i = Θ(n log n).

7. пары 1≤i≤j≤n: n(n+1)/2 = Θ(n²).

Чтобы код структур запускался

Неопределённое поведение (UB). Язык C++ ничего не обещает: падение, тихий неверный ответ, разное поведение на разных машинах.

Частые источники: нет return; неинициализированная переменная; выход за границу массива/вектора; испорченный итератор.

Своими словами. Компилятор не обязан «поймать ошибку». Иногда UB выглядит как «случайно работает», пока не сменишь флаги оптимизации.

Пример. int a[4] — индексы только 0…3. Запись a[4]=7 уже UB.
Предупреждения: -Wall -Wextra -Wshadow. Для libstdc++ до заголовков: #define _GLIBCXX_DEBUG.
Указатели. *p — значение по адресу, &x — адрес, p->x = (*p).x. Имя массива → указатель на нулевой элемент.
int value=3; int* ptr=&value; *ptr=7; → value стало 7.

Что дорого, хотя в Θ не видно

Асимптотика считает шаг единицей; на машине единицы разные.

  1. посимвольный ввод/вывод ≪ чтение буфером;
  2. √, sin, atan — не одна «железная» команда;
  3. деление/остаток дороже сложения и сдвига;
  4. последовательный a[i] дружит с кешем; случайный a[p[i]] — нет;
  5. new/delete → аллокатор;
  6. глубокая рекурсия → Θ(n) кадров стека.

Своими словами. Два алгоритма с одним Θ(n²) ведут себя по-разному, если один держит таблицу n×n в RAM, а другой — массив длины n в кеше.

Пример. Θ(2ⁿ) времени и Θ(2ⁿ) памяти при n≈40 часто убивается памятью раньше времени. Плотный массив обычно быстрее россыпи мелких объектов.

Память слоями (как на лекции — «кубики» с границами)

Диск — самый большой и самый медленный. Оперативная память — гигабайты. Кеш последнего уровня — единицы мегабайт. Ближний кеш ядра — десятки килобайт. На картинке снизу вверх: больше и медленнее → меньше и быстрее. Границы слоёв — жёсткие: данные «живут» в одном кубике, пока их не перенесли ближе к процессору.

Слои памяти как кубики с границами: чем выше — тем меньше объём и тем быстрее доступ.

Зачем кубики. Последовательный проход a[i] читает соседние ячейки — они часто лежат в одном «кубике» кеш-линии: одна загрузка обслуживает несколько итераций. Случайный a[p[i]] прыгает по разным кубикам — кеш не помогает.

Плотный массив обходит кубики подряд; разрозненные объекты — прыжками.

⚡ Быстрый тест: в чат Cursor напиши тест что-дорого-хотя-в-θ-не-видно — несколько коротких вопросов по всему блоку, потом сверка.

Префиксные суммы

Задача. Много раз считать сумму на [l, r]. Наивно — Θ(r−l+1) на запрос → при n запросах легко Θ(n²).

sum[0]=0, sum[i+1]=sum[i]+a[i].
Сумма a[l]+…+a[r] = sum[r+1] − sum[l] за Θ(1) после предобработки Θ(n).

Своими словами. sum[k] — сумма первых k элементов. Отрезок [l, r] = «первые r+1» минус «первые l».

Пример. a=[3,1,4,1] → sum=[0,3,4,8,9]. Сумма индексов 1…2: 1+4=5 = sum[3]−sum[1]=8−3. ✓
Весь массив: sum[n]. Один элемент a[i]: sum[i+1]−sum[i].
Оранжевые sum-кубики: граница отрезка. Разница двух префиксов = сумма зелёных ячеек a.

Когда ломается. Присваивание a[i]=x портит все префиксы правее i. Если обновления и запросы чередуются — одного префикса мало (см. разности и задачу 30).

Разностный массив

Задача. Нули длины n; q запросов «прибавить x на [l, r]»; хочется O(n+q), не O(n·q).

На запрос: d[l]+=x; если r+1 < n, то d[r+1]−=x. Итоговый a — префиксные суммы d.

Своими словами. В l «включаем» +x, в r+1 «выключаем». Префикс размазывает прибавку по отрезку.

Пример. n=5, «+5 на [1,3]».
d=[0,+5,0,0,−5] → a=[0,5,5,5,0]. ✓
Два кубика-события в d → целый отрезок зелёных кубиков в a.
Не-пример ожидания. Две ячейки d не дают «сумму на [L,R]» — d хранит изменения относительно соседа (задача 30).

Массив, списки, вектор

Массив

Массив = ряд кубиков. Список = кубики со стрелками. Вектор = живые + запасные кубики.

Чтение/запись по индексу Θ(1). Поиск значения Θ(n). Удаление с конца (если длина хранится) Θ(1); с начала — Θ(n) из‑за сдвига.

Двусвязный список

Узел: prev, next, значение. Фиктивные head и tail: живые элементы строго между ними. Пустой список: head→tail и tail→head.

Оба конца и erase по известному указателю — Θ(1). Доступ по индексу — Θ(i). Фиктивные узлы убирают ветки «удаляем первый/последний».

Задача 6. В пустом списке head.next указывает на tail.

Односвязный (только head)

push_front Θ(1). push_back без хвоста Θ(n). Удаление середины по указателю на узел за Θ(1) невозможно — нет prev.

Задача 4. push_front Θ(1); push_back Θ(n).

Список индексами

next — номер ячейки в vector. Плотнее по кешу, чем россыпь new. Свободные индексы — стек дырок.

Вектор

Буфер + n + cap. При переполнении ёмкость ×2, копируем живые. n успешных push_back суммарно Θ(n) → амортизированно Θ(1). Рост cap на +1 каждый раз → Θ(n²).

Нельзя стартовать с cap=0 и удваивать: 0·2=0. Первая ёмкость — 1.

Задача 5. Заняты 8 ячеек, удвоение → копируется 8 старых элементов.

⚡ Быстрый тест: в чат Cursor напиши тест массив-списки-вектор — несколько коротких вопросов по всему блоку, потом сверка.

Стек — столбик кубиков. Очередь — очередь кубиков. Кольцо — занятые кубики с переходом через край.
Кольцевой буфер. Длина sz; данные на полуинтервале [start, end) по кольцу. Число элементов: (end−start+sz) mod sz. Картина start=end бывает и у пустого, и у полного — нужен счётчик или свободная ячейка. При удвоении копировать в логическом порядке со start.

Стек и очередь с минимумом; окно

Стек с минимумом

Два стека: data и mins (минимум на префиксе от дна до вершины). push кладёт в оба; pop снимает оба; get_min — вершина mins, Θ(1). Если минимум дважды — две копии в mins.
Задача 2. Кладут 6,4,5 → data=[6,4,5], mins=[6,4,4]. Вершина минимумов = 4.
Стек минимумов — два столбика кубиков. Окно — подсветка кубиков массива + дек кандидатов.

Очередь с минимумом

Два стека с min: b — хвост (push), a — голова (pop). Если a пуст — перелить b→a. min очереди = min вершин a и b. Каждый элемент в b один раз и в a ≤ одного раза → серия m операций суммарно Θ(m).

Своими словами. Одна переменная «текущий минимум» после pop этого элемента не знает нового ответа — поэтому нужен стек префиксных минимумов.

Минимум скользящего окна

Дек индексов: значения возрастают от головы к хвосту; голова — минимум. Новый элемент выкидывает с хвоста всех ≥ него. С головы снимают индексы вне окна. Каждый индекс входит/выходит ≤1 раза → Θ(n) на n окон.

Семинар · средние 8–21

8. Общие элементы

Условие. Два отсортированных массива; пересечение за O(n+m).

Идея. Указатели с начал. Меньший двигаем вперёд (он меньше всего хвоста другого). Равны — в ответ, оба++. Назад незачем.

Пример. A=[1,2,4,5], B=[2,3,5,6] → 2, 5.

9. Два конца

Условие. Отсортированный массив; есть ли пара с суммой S?

Идея. i слева, j справа. Сумма > S → j−− (с этим j меньшие i только увеличат сумму). Сумма < S → i++. ≤ n шагов.

Пример. [1,2,4,7], S=8 → 1+7=8.
Кубики i и j — границы; середину не трогаем, пока не сдвинули конец.

10. Окно с суммой S

Условие. Элементы положительны; подотрезок суммы ровно S.

Идея. Сумма < S → расширяем r; > S → сдвигаем l. Положительность даёт монотонность. Иначе см. задачу 25.

11. Минимум в окне

Условие. Для каждого окна длины k — минимум.

Идея. Монотонный дек индексов (раздел выше). Θ(n).

12. Ближайший меньший слева

Условие. Для каждой позиции — ближайший слева строго меньший.

Идея. Стек возрастающих индексов. Пока вершина ≥ a[i] — снимаем. Новая вершина — ответ; кладём i.

Пример. [2,1,4,3] → слева: нет, нет, 1, 1.

13. Самый тяжёлый подотрезок

Условие. Подотрезок максимальной суммы; sum[r+1]−sum[l].

Идея. Для каждого r: текущий префикс минус минимум префиксов строго левее. Помним один min_prefix и max разности.

14. Не больше k нулей

Условие. Массив 0/1; самый длинный подотрезок с ≤ k нулями.

Идея. r растёт; при нулях > k двигаем l. Каждый конец ≤ n раз.

15. Две стенки

Условие. max min(h[i],h[j])·(j−i).

Идея. Указатели с концов; сдвигаем более низкую сторону (с ней при меньшей ширине лучше не будет).

16. Лодки

Условие. Веса ≤ W; лодка ≤ W и ≤ 2 человека; минимум лодок.

Идея. Сортировка; лёгкий+тяжёлый: если влезают — оба, иначе тяжёлый один. O(n log n).

17. Сколько окон не тяжелее S

Условие. Положительные элементы; число подотрезков суммы ≤ S.

Идея. Для каждого r подогнать l; число окон с этим r: r−l+1. l только растёт.

18. Слияние

Условие. Два отсортированных → один за O(n+m).

Идея. Всегда берём меньшую голову; хвост дописываем.

19. Прибавление на отрезке

Условие. q запросов +x на [l,r]; итоговый массив за O(n+q).

Идея. Разностный массив + один префиксный проход.

20. Три цвета

Условие. Переставить 0,1,2 подряд; один проход, O(1) памяти.

Идея. lo / i / hi. 0 — swap с lo, оба++; 2 — swap с hi, hi−−, i не двигаем; 1 — i++.

21. Ближайший больший справа

Условие. Для каждой позиции — ближайший справа строго больший.

Идея. Стек убывающих; когда пришёл больший — он ответ для снятых.

Семинар · сложные 22–30

22. Прямоугольник под гистограммой

Условие. Макс. площадь прямоугольника под столбцами высоты h[i].

Идея. Монотонный стек: для каждого столбца границы, где он минимум; площадь = h[i]·ширина. Каждый столбец кладётся/снимается один раз.

23. Сумма ограниченной длины

Условие. Макс. сумма подотрезка длины ∈ [L,R].

Идея. Для правого r нужен min префикса на окне индексов — структура задачи 11. Ответ = max(sum[r+1] − min).

24. Вода между столбцами

Условие. Сколько воды удержится.

Идея. Два указателя + left_max/right_max; двигаем более низкую сторону.

25. Где два указателя врут

Контрпример к задаче 10. Массив 3, −5, 4 и S=−1. Подотрезок [−5,4] есть, но монотонное правило «мало — вправо, много — влево» не обязательно его найдёт: сумма окна не монотонна.

Как правильно. Множество уже виденных префиксов; текущий P закрывает сумму S ⇔ раньше был P−S (включая 0). Сортировка префиксов забывает порядок индексов.

26. Коридор max−min ≤ k

Идея. Два дека (min и max) + сдвиг l, пока разброс > k. Каждый индекс входит/выходит ≤1 раза.

27. Три слагаемых = S

Идея. Сортировка; фиксируем i, на хвосте два указателя → O(n²). Без сортировки сдвиг врёт (пример 1,5,2,4 и S=7).

28. Сумма минимумов всех подотрезков

Идея. Для i границы L (слева ≤) и R (справа <); вклад a[i]·(i−L)·(R−i). Два прохода монотонным стеком.

29. Сумма ⋮ k

Идея. Одинаковый остаток префиксов mod k → подотрезок между ними кратен k. Счётчики остатков; пустой префикс = 0 с начала.

30. Граница разностей

Разбор. Разностная ячейка — не сумма на отрезке. Наивный пересчёт префикса перед каждой суммой при Θ(n) запросах → Θ(n²). Если сначала все прибавления, потом все суммы — diff+префикс ещё спасает. Смешанный порядок — нужны структуры вне этих двух лекций.
